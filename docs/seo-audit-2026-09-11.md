# Audit SEO Wallverse — 11 septembre 2026

## Diagnostic

Le site avait un catalogue riche, des liens de fiches descriptifs et des images WebP, mais sa découverte par les moteurs dépendait fortement du JavaScript.

| Contrôle avant correction | Constat vérifié | Correction |
| --- | --- | --- |
| `/robots.txt` | HTTP 200, mais HTML de l'accueil | Fichier texte valide déclarant le sitemap |
| `/sitemap.xml` | HTTP 200, mais HTML de l'accueil | Index XML dynamique et sous-sitemaps avec images |
| URL inventée | HTTP 200, accueil | Vraie page 404 |
| Fiche `/wallpaper/...` sans JavaScript | HTML générique de l'accueil | Titre, description, canonique, contenu et données structurées rendus sur Cloudflare |
| Découverte du catalogue | Images injectées après chargement du JavaScript | Catalogue HTML paginé et 11 catégories reliées à l'accueil |
| Canonique accueil | Absente | URL canonique explicite |
| Titres et partage | Présentation de marque générique | Positionnement smartphone/Android, balises sociales complètes |
| Pages privées | Absence de directive explicite | `noindex,follow` sur profil personnel et notifications |

## Ce qui est livré

- `/wallpapers/` : catalogue public paginé, 24 images par page.
- 11 pages thématiques : anime, gaming, nature, abstract, fantasy, cyberpunk, space, minimalist, movies-tv, sport et miscellaneous. Toutes comportaient des images lors du contrôle.
- `/sitemap.xml` : découverte automatique de 1 415 images approuvées non suggestives au moment du test, réparties en deux sous-sitemaps. Le nombre évolue avec le catalogue.
- Fiches existantes conservées : le serveur produit le contenu initial, puis la fiche interactive habituelle s'ouvre. Le correctif de défilement mobile reste actif.
- Redirection permanente des anciens slugs vers le titre canonique. La règle de slug est maintenant identique côté serveur, grille et routeur.
- Aperçus suggestifs accessibles par lien et connexion, mais exclus de l'indexation et des sitemaps. Aucun aperçu non flouté n'est ajouté au HTML initial ou aux balises sociales.
- Lectures anonymes des seules données approuvées, sans modification de la base ou des règles d'accès. Cache public de cinq minutes : une modification du catalogue peut donc mettre quelques minutes à se propager.
- Données structurées WebSite/Organization, CollectionPage/ItemList et WebPage/ImageObject. Aucun avis, note ou droit de licence inventé.
- Zoom mobile réautorisé sur l'accueil et les liens de fiches.

Le rendu HTML facilite l'accès au contenu sans dépendre du moteur JavaScript des robots, comme le recommande [Google Search Central](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics). Les sitemaps indiquent les URL canoniques et les images ; ils ne garantissent pas l'indexation. [Documentation Google sur les sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## Vérifications

- Compilation des Pages Functions avec Wrangler 4.131.0.
- `npm run test:seo` contre le serveur Cloudflare local : sitemap, pages, pagination, redirections, 404, HEAD, exclusion suggestive et échappement HTML/JSON.
- Navigateur Chromium mobile 390 × 844 : catalogue sans débordement horizontal, fiche non suggestive, fiche suggestive verrouillée, descente/remontée, fermeture et restauration du titre de l'accueil. Aucune erreur JavaScript relevée pendant ce parcours.
- JavaScript désactivé : titre et image visibles sur la fiche publique ; invitation à se connecter sans image dévoilée sur la fiche suggestive.
- Inspection visuelle de la nouvelle page Anime sur mobile.

### Performance observée avant modification

Une navigation sur l'accueil en Chromium local, viewport mobile, sans simulation de réseau lent, a donné un LCP de 2 284 ms et un CLS de 0,0038. Ce sont des mesures ponctuelles de laboratoire, pas des Core Web Vitals réels au 75e percentile. Aucun score Lighthouse, INP réel ou résultat Search Console n'a été obtenu. Les tailles de transfert observées ne couvrent pas nécessairement toutes les ressources externes, à cause des restrictions Resource Timing.

Les mesures terrain restent à suivre dans Search Console/CrUX ; [web.dev explique cette distinction et les métriques](https://web.dev/articles/vitals). Les corrections de ce lot ciblent surtout l'exploration et l'indexabilité, sans promettre un gain de vitesse chiffré.

## Prochaines actions pour gagner des positions

1. Vérifier la propriété `wallverse.win` dans Google Search Console et Bing Webmaster Tools, puis soumettre `https://wallverse.win/sitemap.xml`. Le fichier robots la déclare déjà. Aucun accès à ces comptes n'a été utilisé et aucune soumission manuelle n'est revendiquée. [Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Bing](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed).
2. Mesurer les impressions, clics, pages indexées et requêtes par catégorie. Commencer par des expressions précises comme « anime phone wallpapers », « space phone backgrounds » et les noms d'œuvres, en complément de « smartphone wallpapers ».
3. Enrichir progressivement les descriptions des œuvres et les pages thématiques avec du contenu utile et original. Beaucoup d'images n'ont pas encore de description ; un texte générique ne remplace pas une description éditoriale de l'image.
4. Obtenir des liens pertinents depuis les profils des créateurs, communautés et publications présentant réellement Wallverse. Éviter les achats massifs de liens et la répétition artificielle de mots-clés.
5. Le site étant en anglais, les nouvelles pages ciblent principalement les recherches anglophones. Pour « fond d'écran smartphone », prévoir de vraies pages françaises localisées avec navigation et contenu traduits, puis `hreflang` ; pas seulement une liste de mots français dans les métadonnées.
6. Les profils publics de créateurs restent une piste ultérieure de rendu serveur ; ce lot se concentre sur les wallpapers et leurs catégories.

Une bonne base technique rend les pages éligibles et compréhensibles. Elle ne garantit ni la première page ni une position précise, surtout sur les expressions très concurrentielles. Le contenu, la réputation et les résultats mesurés guideront les étapes suivantes. [Guide SEO de Google](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [consignes Bing](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a).

## Maintenance

- Installer les outils : `npm ci`.
- Serveur local : `npm run dev -- --compatibility-date=2026-09-11`.
- Compiler : `npm run check:functions`.
- Vérifier localement : `npm run test:seo`.
- Vérifier la production : `npm run test:seo -- https://wallverse.win`.
- Les tests de smoke utilisent un lien suggestif connu ; mettre cette fixture à jour si l'œuvre est supprimée ou reclassée.
- La configuration publique est lue depuis `wallverse-data-runtime-0820a.js`. Si ce fichier de référence est remplacé, mettre à jour `lib/seo.js` et relancer les tests.
- Les Pages Functions utilisent `env.ASSETS` et l'API de cache Cloudflare. Pas de nouvelle clé secrète, infrastructure payante provisionnée ni changement de politique d'accès Supabase.
